Automated Documentation Workflow

End-to-End lifecycle mapping the Documentation Agent, reusable skills, and human checkpoints

Workflow Phase Breakdown & Explanatory Notes

Phase Description & Purpose Documentation Agent Interaction Outputs / Artifacts
1. Scope Identification Detects and establishes boundaries for changes, features, or investigations requiring documentation updates. Active Uses change-impact-analyzer to map modified APIs and identify target audiences. Documentation Scope Specification
2. File/Logic Analysis Analyzes source code AST, signatures, models, and tests without hallucinating or inventing unsupported behavior. Active Uses evidence-extractor to pull typed contracts, parameters, return types, and exceptions. Extracted Fact Base & API Contracts
3. Inline Documentation Application Applies standardized docstrings (Sphinx/Google format), type annotations, and module header docs directly to code. Active Drafts and formats accurate inline docstrings directly matching the extracted fact base. Documented Source Files
4. Sphinx Automation & Generation Executes the build pipeline to compile documentation via sphinx-apidoc and make html / sphinx-build. Pipeline Tooling (Automated Sphinx compilation of docstrings and .rst tree into HTML/PDF). Static HTML Web Portal & API Reference
5. Review & Maintenance Validates generated docs, verifies accuracy, checks edge claims, and obtains human sign-off before publishing. Active Uses review-packager to package diffs, evidence links, and checklists for human review. Engineering Review Package → Published Docs
